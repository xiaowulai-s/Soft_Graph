## 推送过程中遇到的两个坑（重要）

### 坑一：环境代理指向了一个已失效的代理端口

构建环境导出了 `HTTP_PROXY=HTTPS_PROXY=http://127.0.0.1:6711`。
Git 会读取这两个环境变量，把 GitHub 的请求全部发给该本地代理，而该端口实测 `ECONNREFUSED`
（此前一度返回 `HTTP 502`），因此 `git push` 报出误导性的：

```
schannel: server closed abruptly (missing close_notify)
```

**这不是 TLS 或认证问题，而是被一个坏代理挡住了。**

### 坑二：直连其实一直是通的

绕过代理后探测结果（同一环境）：

| 探测项 | 结果 |
|---|---|
| DNS 解析 `github.com` | 20.205.243.166 |
| TCP 直连 `github.com:443` | ✅ OK（103 ms） |
| HTTPS GET `/xiaowulai-s/Soft_Graph.git/info/refs` | ✅ HTTP 200（579 ms） |
| 经代理 `127.0.0.1:6711` | ❌ ECONNREFUSED |

**正确做法：清空代理环境变量后直连推送。**

```bash
cd D:\Demo\Graph\softgraph

# 清空代理变量（关键一步）
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY

# 双保险：显式覆盖 git 的代理配置为空
git -c http.proxy= -c https.proxy= push -u origin main
```

凭据由系统凭据管理器提供，无需每次输入。
若确实需要走代理，请改成可用的代理地址（而不是已失效的端口）：

```bash
git -c http.proxy=http://127.0.0.1:<可用端口> push -u origin main
```

