## 🔴 修复类（真缺陷，建议优先）

### F1 插件「更新」会丢失授权
- **现状**：市场更新 = `removeExternal`（内部调用 `approvals.revoke`）+ 重新安装。已核实的代码路径：registry.ts:225。
- **问题**：每次更新插件，用户之前的 fs/network/powershell 授权被撤销，需重新授权——生态使用体验断层。
- **选项**：
  - **a**（推荐）：registry 新增 `updateSource(source, origin)`——校验同 id + 直接原子覆盖插件文件 + reload，**授权记录保留**；市场更新改走此通道。
  - **b**：removeExternal 加 `keepApprovals` 参数，更新流程保留授权记录。
- **建议**：a（覆盖文件本就是更新的正确语义，顺带消除「卸载→装」中间态窗口）。

### F2 浅色主题残留硬编码色
- **现状**：JunkSidebar 仪表盘统计卡（#E1F5EE/#E6F1FB/#FAEEDA）与 MaintenanceCenter 5 处未走 CSS 变量；浅色主题下观感割裂。
- **选项**：a（推荐）全部 token 化（统计卡三色进 theme.css 变量，双主题各配一套）；b 保持现状仅深色为主。
- **建议**：a，工作量 1 小时内。

### F3 locks 测试 flaky（psbridge 长序列超时）
- **现状**：全套 488 跑时「RM 通道」用例 60s 超时（单跑 3s 通过）——psbridge 会话池在长序列下状态劣化，已复现两次。
- **选项**：
  - **a**（推荐）：psbridge 会话池增强——空闲会话主动回收 + 执行前健康探测 + 超时重试一次（治本）；
  - **b**：仅给该用例加重试装饰（治标）。
- **建议**：a。

### F4 Gitee 令牌轮换
- **现状**：私人令牌曾在对话中明文出现（虽然已存 gitignored 的 `.keys/gitee-token`）。
- **建议**：Gitee 后台吊销旧令牌 → 生成新令牌（仅 projects 权限）→ 更新 `.keys/gitee-token`。一条消息的事，纯安全卫生。

## 体验类

### E1 图谱签名色无图例
- **现状**：节点描边已按签名着色（绿/amber），但图例未说明，用户不知色含义。
- **建议**：图例加两项（绿点 已签名 / amber点 签名未知），0.5 小时。

### E2 垃圾清理双实例状态不同步
- **现状**：图谱侧栏与垃圾清理主视图是两个 JunkSidebar 实例，勾选状态各自独立。
- **选项**：a（推荐）勾选状态提升到 App 级共享（Pinia store）；b 保持现状（影响小）。
- **建议**：a，1~2 小时。

### E3 系统通知可点击跳转
- **现状**：有新版本的系统通知点了没反应。
- **建议**：click → 聚焦主窗口 + 跳维护中心「扫描与更新」。1 小时。

### E4 releaseNotes 用 Markdown 渲染
- **现状**：更新日志纯文本截断 400 字。
- **建议**：引入轻量 md 渲染（或简单加粗/列表正则转换），折叠可展开。2 小时。

### E5 维护中心卡片化首屏
- **现状**：4 组胶囊 + 组内长列表；首屏看不到全局状态。
- **建议**：进维护中心先见 8 张状态卡（每卡：状态摘要 + 点击直达对应组），即上轮 Mockup 的卡片网格。2~3 小时。

## 架构 / 安全（观察项，不建议现在动）

### A1 插件沙箱渐进
- **现状**：插件在主进程内执行、有完整 Node 能力（README 已警示）。生态扩大后风险随之增大。
- **建议**：暂不动；待第三方插件真实增多后，评估 vm 沙箱 collect / API 白名单化（大工程）。

### A2 设置导出/导入 + user 规则区 UI
- **现状**：规则分区模型的 user 区已预留但无 UI；设置无备份手段。
- **建议**：v3.9/v4.0 候选。

### A3 NSIS 卸载清理数据目录选项
- **建议**：installer 加「卸载时保留/删除数据」选项（NSIS 脚本小改）。

### A4 bench 常态化
- **建议**：`npm run bench --quick` 挂到发布前手测清单（已有 docs/10），无需 CI。
