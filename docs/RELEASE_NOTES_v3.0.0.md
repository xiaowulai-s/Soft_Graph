# SoftGraph v3.0.0 —— 软件图谱与磁盘清理工具

v3.0.0 的主线是**把「能跑通」推进到「有真实数字、能长期维护」**：
覆盖率与样本库量化、原生增量能力打通、CI 端到端、浮窗生态扩展、注册表清理全链路。

## 工程基座（M0）

- **单元测试覆盖率量化到 76.5%**（3329+/4351 行）：新增零依赖 sourcemap 还原器
  （`npm run test:cov`），把 esbuild 打包产物的 V8 覆盖率映射回 TS 源文件
- **PE 样本库 19 → 125 个**：12 组采集器覆盖系统 exe/dll、驱动、WinSxS、.NET、
  第三方 x64/x86；`npm run samples:verify` 125/125 零漂移
- 测试规模：**391 用例 / 88 套件全绿**

## 性能与原生能力（M1）

- **重复文件四级过滤**：在三段采样与全文件 SHA-256 之间插入扩展采样（16 段，
  约 1MB 读取量），并给各级哈希加并发。合成数据集 A/B：**−48%**，命中数完全一致
- **USN 变更记录级增量（B1）打通**：提权实测 `fsutil usn readjournal` 返回真实记录，
  据此修正解析器三处错误（USN 字段错位、原因标志位混入、缺失 ID 字段）
- **B1 第 2 级结论定稿**：`partial` 模式**明确放弃** —— 实测「父文件 ID 反查路径」
  （`fsutil file queryFileNameById`）虽无需提权即可用，但单次 158ms 且无批量通道，
  按每轮 200 条变更外推 31.6s，是签名遍历基线的 3 倍以上。只保留 `reuse-all`
- `mapPool` 提取到 `@shared/util`，全链路统一并发口径
- **依赖解析提速 68%（A7）**：分段实测把靶子从「PE 解析」纠正到两处真瓶颈 ——
  ① E4 .NET 程序集定位的穷举缺陷（Docker Desktop 单软件 **12.9s → 11ms**）；
  ② 安装目录快照完全串行的逐文件 stat。5 样本累加 **30701ms → 9881ms**，
  图谱输出逐项一致。**未做 PE 解析 worker 池**（实测只占 0.3%，做了等于白做）
- **图标按需加载（A2）**：新增提取队列（去重 + 250ms 聚批 + 就绪推送），
  渲染层从 **250 次串行 IPC** 降为 1 次批量调用；扫描后预热可关（`SG_ICON_PREWARM=0`）
- **便携目录 mtime 缓存（A3）**：目录 mtime + 条目数 + 主 exe mtime 三重签名，
  `installedPaths` 指纹 / 手动标记 / TTL 四重失效。真机 36 个候选 **冷 37ms → 热 2ms**，结果逐字段一致
- **全库文件检索（I-11）**：新增顶栏「检索全库文件」（前缀/子串可切、结果含引用数），
  命中项直接打开该文件的反向依赖子图 —— 覆盖「当前软件图谱里没加载」的文件。
  数据层用**写入侧算好的小写派生列 + 范围比较**，`EXPLAIN` 证实命中索引
  （`LIKE 'q%'` 的查询计划是 `SCAN`，索引完全用不上，因此不用它）

## 交付与回归（M2）

- **CI 接入 CDP 端到端**：`npm run e2e:ci` 自动启动应用 → 等调试端口 → 驱动真实交互
  → 关闭；CI 新增 `e2e` 作业并上传截图
- 真机回归：软件扫描 250 条目 · 图谱构建 · 垃圾扫描 13 分类 / 91.1 GB

## 浮窗生态（M3）

- **内置插件 7 → 12**：新增温度与风扇（三级 WMI 源）、电池与电源、
  网络连接（连接数 + TOP 进程）、专注计时，以及 **CPU 占用 TOP**
  （用瞬时占比 `PercentProcessorTime` 而非累计的 `Get-Process.CPU`，按核数归一化）
- **浮窗多实例（F4）**：每个实例独立插件组合 / 位置 / 尺寸 / 主题 / 穿透，
  可分布到多显示器；拖拽与悬停按来源窗口分发
- **设置页实例管理**：增删实例、逐实例插件勾选与排序、实例级外观与行为；
  应用级行为（总开关 / 触发条宽度 / 置顶）单独成组
- 向后兼容：老配置（无 `instances` 字段）自动折叠为默认实例，
  单实例行为逐字段等价（有专门断言钉死）

## 注册表清理（M4）

- 枚举三条 Uninstall 子树（HKLM 64/32 + HKCU）→ 残留判定 → 白名单校验
- **完整 UI 链路**：扫描 → 列表勾选 → 三级确认（列表 → 影响清单 + 知悉勾选 →
  输入「清理注册表」）→ 先备份后删除 → 审计留痕
- **从备份还原**：列出快照一键恢复，还原路径强制限定在备份目录内
- 安全约束：白名单硬编码（只允许 `...\CurrentVersion\Uninstall\*`）、
  **先备份后删除**（备份失败即拒绝）、不提权时明确返回 `needsElevation`、
  JSON 快照含子键与值可完整还原、**渲染层只回传键路径**（主进程重新枚举后二次校验白名单）
- 真机验证：252 个键，白名单 252/252 通过；收紧判定后仅 1 条真实残留

## 修复的缺陷

| 级别 | 缺陷 |
|---|---|
| 高 | **环境块膨胀导致 P/Invoke 能力静默全灭** —— 宿主环境块超 64KB 上限时 PowerShell `Add-Type` 失败，API Set 映射与占用检测不报错只返回空；现传白名单最小环境 |
| 高 | **注册表误报** —— 把 `SystemComponent=1` 的系统隐藏项（本机 37 条）与 Paint/截图工具等内置应用判成残留，删除会破坏系统注册 |
| 高 | **E4 .NET 程序集定位穷举** —— `hits > 120` 语义写错（统计命中数而非处理数），未命中的引用会穷举全部运行时目录、每条约 10 次注定失败的 `fs.access`。Docker Desktop 单软件 12.9s（占其解析耗时 99.6%），最终只产出 192 条边 |
| 高 | **对新列建索引写在建表语句里** —— 老库的 `file_index` 没有该列，`CREATE INDEX` 抛「no such column」使 `init()` 失败、应用起不来。索引改到补列迁移之后 |
| 中 | 电池插件把「无电池」显示成「电量 0%」（`Number(null) === 0`）；USN 解析器 USN 字段错位一格 |
| 中 | **浮窗已开启时新增实例不显示窗口**（`sync()` 只创建管理器，窗口要显式 `open()` 才出现） |
| 中 | 浮窗实例规范化在主进程与渲染层各写一份会漂移 → 提取到 `@shared/float` 单一实现 |
| 中 | **便携缓存漏缓存「低分候选」** —— 命中率 30.6% → 50.0%，热扫描 37ms → 2ms |
| 中 | 测试运行器整目录删除失败会打断测试链路（改为降级逐个清理） |
| 低 | 测试注释与实现不符（内置插件数量 / 行数）；`store.ts` 关于「退化为 LIKE + 前缀索引」的注释与实际（零实现）不符；`Remove-Item` 被占用时静默失败 |

## 未完成项（后续补全后仍以 3.0.0 提交）

- 需外部资源：**C1** 双基线回归（缺 Win10 机器）、**E1** 正式签名（缺 OV/EV 证书）
- 未达成验收：USN 增量 ≤5s（已定稿为降级，见 M1 一节）、样本库 500+（现 125 个，需多机器样本池）
- 经实测**排除**（不再列为待办）：B1-L2 `partial` 模式（反查成本 3 倍于收益）、
  A7 PE 解析 worker 池（PE 解析仅占 0.3%）

> 已补全：注册表清理界面、备份还原入口、浮窗实例管理界面、`sys.topcpu` 插件（内置 12 个）、
> A2 图标按需加载、A3 便携 mtime 缓存、A7 依赖解析提速、I-11 全库文件检索。
