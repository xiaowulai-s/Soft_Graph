# 浮窗插件开发指南

SoftGraph 的桌面浮窗采用插件化架构：**新增一个监控项 = 新增一个 .js 文件，主程序零改动**。

内置插件（CPU/内存、磁盘、网速、时钟、垃圾体积、系统概览、内存 TOP 进程）与外部插件走**完全相同**的契约，
因此内置插件也可以被禁用、排序、替换。

## 30 秒上手

1. 打开插件目录：`%LOCALAPPDATA%\SoftGraph\plugins\`（设置页「浮窗 → 打开插件目录」）
2. 复制 `example-hello.js` 为 `my-plugin.js`，改 `manifest.id` 与 `name`
3. 设置页点「重载插件」——无需重启应用

## 插件结构

```js
module.exports = {
  manifest: {
    id: 'vendor.name',      // 唯一 id；与内置插件冲突会被拒绝加载
    name: '显示名称',
    description: '一句话说明',
    interval: 3000,         // 采集间隔（毫秒）；0 = 仅在手动刷新时采集
    view: 'bars',           // metric | gauge | bars | list | text
    icon: 'plugin',         // 图标键，见下方图标表
    version: '1.0.0',
    author: '作者'
  },

  async setup(ctx) { /* 可选：注册常驻采集器 */ },
  async collect(ctx) {                       // 必需：返回数据数组
    return [{ label: '标签', value: '值', ratio: 42, tone: 'normal' }]
  },
  dispose() { /* 可选：释放资源 */ }
}
```

### 数据项字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `label` | string | 左侧标签 |
| `value` | string | 右侧数值（已格式化好的字符串） |
| `ratio` | number? | 0~100，`bars` / `gauge` 视图用它画进度 |
| `hint` | string? | 卡片底部补充说明 |
| `tone` | `'normal' \| 'good' \| 'warn' \| 'danger'` | 数值颜色 |

### 五种视图

| view | 渲染形态 | 适用场景 |
|---|---|---|
| `metric` | 标签 + 值，多行 | 上传/下载速率、磁盘剩余 |
| `bars` | 标签 + 值 + 进度条 | CPU、内存、各分区占用 |
| `gauge` | 环形进度 + 中心数值 | 单一核心指标 |
| `list` | 名称 + 值列表 | TOP 进程、概览信息 |
| `text` | 首行大字 + 次行小字 | 时钟 |

## ctx 能力

| 成员 | 说明 |
|---|---|
| `ctx.formatBytes(n, digits)` | 字节数格式化（B/KB/MB/GB/TB） |
| `ctx.state` | `Map`，跨轮次保存状态（例如上一次计数器值，用于算速率） |
| `ctx.app.softwareCount()` | 已收录软件数 |
| `ctx.app.junkTotalBytes()` | 上次扫描的可释放空间 |
| `ctx.app.junkOneClickBytes()` | 一键可清理空间（仅低风险默认勾选类） |
| `ctx.app.quarantineCount()` | 隔离区条目数 |
| `ctx.app.lastJunkScanAt()` | 上次垃圾扫描时间戳；未扫描返回 `null` |
| `ctx.psJson(script, timeoutMs)` | 执行 PowerShell 并取 JSON（脚本内用 `Write-SgJson` 输出） |
| `ctx.log(...)` | 打日志到主进程控制台（前缀 `[plugin:<id>]`） |

## 图标键

`cpu` `disk` `network` `clock` `trash` `graph` `process` `plugin` —— 未匹配的键渲染为 `•`。

## 示例：计算速率（跨轮次状态）

```js
module.exports = {
  manifest: { id: 'demo.rate', name: '示例速率', interval: 2000, view: 'metric', icon: 'network', version: '1.0.0' },
  collect(ctx) {
    const now = Date.now()
    const prev = ctx.state.get('last')
    const cur = Number(process.uptime().toFixed(1)) // 示例计数
    ctx.state.set('last', { v: cur, ts: now })
    if (!prev) return [{ label: '速率', value: '采样中…' }]
    const dt = Math.max((now - prev.ts) / 1000, 0.5)
    const rate = (cur - prev.v) / dt
    return [{ label: '速率', value: rate.toFixed(2) + '/s', tone: rate > 1 ? 'good' : 'normal' }]
  }
}
```

## 示例：调用 PowerShell

```js
async collect(ctx) {
  const rows = await ctx.psJson(`
    $p = Get-Process -Id $PID
    Write-SgJson ([pscustomobject]@{ ws = [double]$p.WorkingSet64 })
  `, 8000)
  return [{ label: '自身内存', value: ctx.formatBytes(rows.ws) }]
}
```

## 约束与容错

- `collect` 超过 **15 秒**未返回判超时，错误显示在对应卡片上，其他插件不受影响
- 插件抛错不会导致浮窗崩溃（错误以红色文案渲染在该卡片内）
- 加载失败的插件记录在设置页，可在「重载插件」后查看
- 插件在**主进程**内执行、拥有完整 Node 能力 —— **只安装你信任的插件**

## 布局建议

- 每个插件渲染为一张卡片，按设置页中的顺序自上而下排列
- 建议单插件数据项 ≤ 4 条，避免浮窗过高
- 需要长期运行的采集器放 `setup()`，用 `dispose()` 清理定时器/子进程
