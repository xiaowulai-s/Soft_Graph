## 与 SoftGraph 定位的映射（按契合度排序）

### ★★★★★ S1 自启动管理（生命周期闭环的最大缺口）
- **对标**：BootLens / fancyStart / Autoruns
- **现状缺口**：SoftGraph 已覆盖「安装 → 升级 → 清理 → 卸载」，唯独缺「**开机自启**」——这正是用户感知"软件变慢变卡"的第一现场。
- **建议功能**：维护中心新胶囊「自启动」——
  - 多源聚合：HKCU/HKLM Run、启动文件夹、计划任务（复用现有提权/PS 通道）
  - 每项显示：发布者 + 签名状态（**签名数据已有**，直接复用 trust 色标）+ 文件是否仍存在
  - 一键启用/禁用（Autoruns 兼容的 AutorunsDisabled 子键方式，可逆）
  - 与图谱联动：自启项在软件图谱高亮关联
- **工作量**：2~3 天（多源枚举 1.5 天 + UI 0.5 天 + 提权处理 0.5 天）

### ★★★★★ S2 磁盘空间树图（GC-12 的可视化升级）
- **对标**：windirstat / squirreldisk
- **现状缺口**：GC-12 超大文件是**列表**，缺少"空间去哪了"的直观视图。
- **建议功能**：垃圾清理视图加「树图」模式——软件体积/目录占用用交互式 treemap（d3-hierarchy 现成），点击块 → 定位文件 → 接现有清理/隔离链路。
- **工作量**：2 天（d3 treemap 布局 + 现有扫描数据适配）

### ★★★★☆ S3 一键启动 / 应用快捷启动
- **对标**：Flow.Launcher
- **现状缺口**：SoftGraph 知道所有软件装在哪（mainExe），却不能**启动**它们——数据在手白白浪费。
- **建议功能**（三段递进）：
  - a. 软件列表/图谱节点右键「启动」（已有 reveal，加 launch 一行）——半天
  - b. 浮窗官方插件「我的应用」：常用应用卡片点击启动——半天
  - c. 全局热键唤起启动面板（Flow.Launcher 式）——1~2 天
- **工作量**：a+b 一天，c 再加 1~2 天

### ★★★☆☆ S4 硬件监控浮窗插件（LibreHardwareMonitorLib）
- **对标**：LibreHardwareMonitor（MPL-2.0，NuGet 类库可直接引用）
- **建议功能**：官方插件「硬件脉搏」——CPU/GPU 温度、内存/磁盘负载卡片（插件生态第一个重头插件，展示 psJson 之外的**原生数据源能力**）。
- **依赖**：LibreHardwareMonitorLib 是 .NET 库，Electron 主进程需走子进程（LHM CLI 模式或 PowerShell + NuGet 打包）——工程复杂度中等偏高；或降级用 PowerShell + `Get-CimInstance`（精度低但零依赖）。
- **工作量**：原生 2~3 天 / CIM 版 1 天

### ★★★☆☆ S5 装机清单（换机场景）
- **对标**：winutil Install Selection
- **建议功能**：软件图谱导出「装机清单」——已装软件列表（名+版本+发布者）一键导出，配合 winget 批量安装命令生成；换机/重装场景刚需。
- **工作量**：1 天

### ★★☆☆☆ S6 系统调优脚本集（谨慎）
- **对标**：winutil Tweaks / optimizer
- **现状风险**：改注册表/服务/遥测属于高破坏面操作，与 SoftGraph「清理可还原」的安全人设冲突；且 winutil 类项目已极卷。
- **建议**：暂不做整集；只挑 2~3 个低风险高感知项（如禁用休眠文件、清理 Windows.old 引导）以「可还原」方式并入 GC 规则体系。后期视需求再议。
