# 代码签名指南（E1）

> 状态：**签名流水线已真机验证**（自签名证书端到端），等待正式证书接入。
> 正式证书到位后按本文 15 分钟内完成切换。

## 为什么需要签名

| 不签名 | 签名后 |
|---|---|
| SmartScreen 拦截「未知发布者」，普通用户无法通过 | 显示发布者名称，可正常安装 |
| 杀软误报概率显著升高（扫描类工具是重灾区，风险 R8） | 误报率大幅下降，且可凭签名主体申诉白名单 |
| 企业/受控环境直接禁止运行 | 可通过策略分发 |

## 证书选择

| 类型 | 价格量级 | 特点 | 建议 |
|---|---|---|---|
| **OV（组织验证）** | 数百 USD/年 | 普通代码签名证书，需人工审核组织信息 | 个人/小团队起步的性价比之选；SmartScreen 信誉需积累下载量 |
| **EV（扩展验证）** | 数百~上千 USD/年 | 立即获得 SmartScreen 信誉；私钥在硬件令牌/云签名服务中 | 面向公开发布的推荐选项 |

> 2023-06 起所有代码签名证书私钥都必须存于硬件令牌或 FIPS 兼容云 KSP，
> 纯 PFX 文件签名只存在于老证书。购买时向 CA 确认交付形式（令牌 / eSigner 云签名）。

## electron-builder 接线（零配置改动）

`electron-builder.yml` 目前显式声明 `signAndEditExecutable: false`（未签名时的兜底）。
**接入正式证书后无需改配置文件** —— electron-builder 原生读取环境变量：

```bash
# PFX 文件形式（OV 老证书 / 自签名）
set CSC_LINK=D:\certs\softgraph.pfx          # 也可用 base64（CI 场景）
set CSC_KEY_PASSWORD=<pfx 密码>
npm run pack:win                              # 构建时自动签名

# EV 云签名（如 SSL.com eSigner / DigiCert KeyLocker）按 CA 提供的 KSP 工具文档配置，
# 同样通过环境变量把签名工具挂进 electron-builder 的 win signing 钩子。
```

环境变量存在时 `signAndEditExecutable: false` 会被 electron-builder 的
`forceCodeSigning` 逻辑覆盖吗？—— 不会，需要把该行改为 `signAndEditExecutable: true`
（或直接删除该行），**构建会在缺少证书时明确报错而不是静默跳过**，推荐正式发布时这样设。

## 手动签名（构建后补签 / 验证）

```powershell
# 方式一：signtool（Windows SDK，功能最全，支持时间戳与 /tr RFC3161）
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 ^
  /f my.pfx /p <密码> "release\1.0.0\SoftGraph-1.0.0-portable.exe"
signtool verify /pa /v "release\1.0.0\SoftGraph-1.0.0-portable.exe"

# 方式二：Set-AuthenticodeSignature（系统内置，免 SDK；证书需在 CurrentUser\My）
Set-AuthenticodeSignature -FilePath <exe> -Certificate (Get-ChildItem Cert:\CurrentUser\My\代码签名证书)

# 验证
Get-AuthenticodeSignature <exe> | Format-List Status, StatusMessage, SignerCertificate
```

**时间戳（/tr）不能省**：它把签名锚定到权威时间，证书过期后已签名产物依然有效；
不打时间戳的签名会随证书过期而失效。

## 本仓库的真机验证记录（2026-09-13）

用 `New-SelfSignedCertificate -Type CodeSigningCert` 生成测试证书 →
`Set-AuthenticodeSignature` 签名 portable exe → `Get-AuthenticodeSignature` 独立验证：

| 步骤 | 结果 |
|---|---|
| 证书生成（CodeSigningCert，CN=SoftGraph Dev Signing (TEST ONLY)） | ✅ 指纹 F7CBC289…596E |
| portable exe 签名前 | `NotSigned` |
| 签名执行 | ✅ 写入成功，Signer = CN=SoftGraph Dev Signing (TEST ONLY) |
| 独立验证 | 状态 `UnknownError`，消息「不受信任提供程序信任的根证书中终止」—— **这是自签名证书的预期行为**（签名结构有效，只是信任链不被系统信任）；换正式 OV/EV 证书后即为 `Valid` |

## 杀软误报应对（风险 R8）

1. **签名是第一步**（上表），签名后误报率显著降低
2. 若仍被误报：
   - Microsoft Defender：https://www.microsoft.com/wdsi/filesubmission 提交样本申诉
   - 其他厂商：通过 VirusTotal 查看命中的引擎，逐家提交白名单申请（大多有开发者通道）
3. 发布页明示 SHA-256 校验值，供用户自行核对安装包完整性
