# SoftGraph v2.0.0 开发计划

> 定位：从「能跑通」到「能日常依赖、可交付给第三方」。
> 三个关键词：**快**（性能达标）、**准**（依赖证据补全）、**稳**（兼容性 + 签名 + 自动化回归）。
> 基线：v1.0.0（2026-09-11 发布，[Release](https://github.com/xiaowulai-s/Soft_Graph/releases/tag/v1.0.0)）

## 二、工作流划分（7 条主线）

### A · 性能攻坚（P0）

| 任务 | 做法 | 预期收益 |
|---|---|---|
| A1 PowerShell 采集并行化 | ① 五类来源拆为并行调用；② 更优选：建立**常驻 PS 会话**（命名管道交互），消除每次 0.3~0.6s 冷启动 | I-01：19s → 6s |
| A2 图标提取懒加载 | 扫描期只算 `iconHash`；图标在列表可见/图谱需要时按需提取并落盘缓存 | 扫描尾段不再被 300+ 次 PS 调用拖住 |
| A3 便携目录扫描优化 | BFS + 并发上限 + **按目录 mtime 缓存**（未变更则复用上次评分） | 二次扫描近乎免扫 |
| A4 重复文件哈希分级 | 三级过滤保留，但把 SHA-256 换成 BLAKE3/xxHash 做采样比对，仅最终确认用强哈希；文件级并行 `worker_threads` | I-02：160s → 100s |
| A5 轻量增量（不依赖 USN） | 按卷记录 `mtime` 水位，仅重扫变更目录——**非 NTFS 卷也适用** | 为 B1 提供兜底与过渡 |
| A6 数据库写入批量化 | sql.js 驱动下合并事务 + 降低整库落盘频率；大结果集分页写 | 消除扫描尾段卡顿 |

**验收**：枚举 ≤ 6s；全盘垃圾 ≤ 100s；缓存命中的图谱构建 ≤ 400ms。

### B · 原生能力补全（P0/P1）

| 任务 | 说明 | 依赖 |
|---|---|---|
| B1 USN Journal 增量（FR-13） | 两条路线：**(a)** 可选原生模块（Rust/Node-API，`optionalDependencies` + 运行时探测，缺失自动降级到 A5）；**(b)** 先用 `fsutil usn readjournal` 读取变更（能力受限，但零原生依赖） | 见「关键决策」 |
| B2 延迟删除落地 | 占用文件登记 `MOVEFILE_DELAY_UNTIL_REBOOT`，下次启动校验并提示结果（补全文档 5.6.1 流程） | 需注册表 `PendingFileRenameOperations` 写入 |
| B3 Restart Manager 占用检测 | 用 `RmStartSession/RmGetList` 定位占用进程，给出「关闭后即可删除」的可操作指引 | 原生调用或 PowerShell 等价实现 |
| B4 E6 证据默认可用 | CLSID 索引落库 + 后台增量更新（首扫后台建索引，之后增量），不再阻塞图谱构建 | 无 |
| B5 API Set 动态映射 | 从 `ntdll` 的 `.apiset` 节读取映射表，替换当前静态前缀表 | 无 |

## 四、关键决策：是否引入可选原生模块 —— ✅ 已决策

**决策结果（2026-09-12）：采用「双轨」方案。**

- 原生模块名：`softgraph-native`，放入 `package.json` 的 `optionalDependencies`
- 加载方式：**运行时 `require` + try/catch**，严禁静态 import（否则无模块环境打包即失败）
- 缺失时自动降级，三项能力各有明确替代路径：

| 能力 | 原生可用 | 缺失时降级为 |
|---|---|---|
| USN Journal 增量 | 读卷变更日志，增量 ≤ 5 s | 按卷 `mtime` 水位增量（非 NTFS 卷同样适用） |
| Restart Manager 占用检测 | 精确定位占用进程 + 登记重启删除 | 移动失败按 `errno` 判定占用并提示关闭进程 |
| API Set 动态映射 | 从 PEB `.apiset` 读映射表 | 内置静态前缀映射表（未命中标记为虚拟而非缺失） |

实现落点：`packages/native/capabilities.ts`（探针 + 降级策略 + 诊断报告输出）。
架构守护：`tests/unit/native.test.ts` 会扫描全仓库，一旦出现对原生模块的静态 import 即测试失败。

### M0 期间发现并修复的缺陷

| 编号 | 缺陷 | 严重度 | 状态 |
|---|---|---|---|
| BUG-05 | 环境变量缺失时，规则根目录退化成 `\Temp` 这类**盘根相对路径**，会放大扫描范围 | 高 | ✅ 已修（展开后强制校验绝对路径） |
| BUG-06 | 零导入模块（`ntdll.dll`、`KernelBase.dll`）被误判为「疑似加壳」，UI 会错误提示未能解析 | 中 | ✅ 已修（新增导出表判定 + 加壳节名识别） |
| BUG-07 | 共享运行库未按文档 5.3 默认成组，图谱噪声偏多 | 中 | ✅ 已修（`collapseSharedRuntime` 默认开启） |
| BUG-08 | 图例中「共享运行库」一项点击无效（伪类型未参与过滤） | 低 | ✅ 已修（统一 `isSharedRuntime` 判定） |
| **BUG-09** | **用户库目录按英文名写死：中文系统 / OneDrive 接管 / 手动重定向到其它盘时全部落空，导致 GC-11（重复文件）与 GC-12（超大文件）静默失效** | **高** | ✅ 已修（读注册表 `User Shell Folders` 解析真实路径 + 新增 `%SG_DOCUMENTS%` 等 token） |
| BUG-10 | 规则多个根目录重叠时（如 `%USERPROFILE%` 与 `%SG_DOCUMENTS%` 指向同一处）同一文件被统计两次 | 低 | ✅ 已修（按路径去重） |

> **BUG-09 的现场证据**：基准机器上 `[Environment]::GetFolderPath('MyDocuments')` 返回 `D:\文档`，
> 图片/桌面/视频/音乐同样全部重定向到 D 盘。修复前 GC-11（重复文件）的 3 个根目录全部不存在，
> 该分类**实际一个目录都没进**，返回 0 项耗时 0 秒 —— 用户却会以为「扫过了」。
>
> 修复后实测（同机）：
>
> | 指标 | 修复前 | 修复后 |
> |---|---|---|
> | GC-11 根目录 | 3 个（全部不存在） | `D:\下载 / D:\文档 / D:\图片 / D:\桌面` |
> | GC-11 结果 | 0 项 · 0 B · 0.00 s | **373 项 · 1.01 GB · 30.6 s** |
> | GC-12 根目录 | 仅 `%USERPROFILE%` | 追加 `D:\文档 / D:\图片 / D:\视频 / D:\音乐` |
> | 识别样例 | — | `D:\下载\CAD格式转换器2023-单文件版.exe` ↔ 微信接收目录同名副本 |
>
> 同时新增**编译期警告**：若某条规则的库目录 token 未解析成功或根目录为空，
> `RuleSet.warnings` 会给出明确说明（避免再次出现「静默失效」）。
