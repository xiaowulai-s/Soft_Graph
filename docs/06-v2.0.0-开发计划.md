# SoftGraph v2.0.0 开发计划

> 定位：从「能跑通」到「能日常依赖、可交付给第三方」。
> 三个关键词：**快**（性能达标）、**准**（依赖证据补全）、**稳**（兼容性 + 签名 + 自动化回归）。
> 基线：v1.0.0（2026-09-11 发布，[Release](https://github.com/xiaowulai-s/Soft_Graph/releases/tag/v1.0.0)）

---

## 一、v1.0.0 实测遗留与问题清单

所有数据来自真机实测（详见 `docs/04-验证报告.md`），不是推测。

| 编号 | 问题 | 现状数据 | 目标数据 | 严重度 |
|---|---|---|---|---|
| I-01 | 软件清单枚举慢 | 19 ~ 28 s | ≤ 6 s | 高 |
| I-02 | 全盘垃圾扫描慢 | ~160 s | ≤ 100 s | 高 |
| I-03 | 无 USN Journal 增量（FR-13） | 每次全量 | 增量 ≤ 5 s | 高 |
| I-04 | E6（COM 注册）证据默认关闭 | 少一类依赖证据 | 默认开启 | 中 |
| I-05 | 占用文件仅计数，未登记延迟删除 | 仅报 `pendingReboot` | 重启后自动完成 | 中 |
| I-06 | 未做 Win10 / 多语言 / 非 ASCII 用户路径回归 | 仅 Win11 23H2 实测 | 双基线通过 | 高 |
| I-07 | 扫描在主进程执行（未做进程隔离） | 崩溃即整体中断 | 崩溃自愈续扫 | 中 |
| I-08 | 无代码签名 | 杀软可能误报（风险 R8） | 签名 + 白名单 | 高 |

| I-13 | 浮窗插件无清单校验、无权限声明 | 插件可任意读写 | schema 校验 + 能力声明 | 中 |

## 二、工作流划分（7 条主线）

### A · 性能攻坚（P0）

| 任务 | 做法 | 预期收益 |
|---|---|---|
| A1 PowerShell 采集并行化 | ① 五类来源拆为并行调用；② 更优选：建立**常驻 PS 会话**（命名管道交互），消除每次 0.3~0.6s 冷启动 | I-01：19s → 6s |
| A2 图标提取懒加载 | 扫描期只算 `iconHash`；图标在列表可见/图谱需要时按需提取并落盘缓存 | 扫描尾段不再被 300+ 次 PS 调用拖住 |
| A3 便携目录扫描优化 | BFS + 并发上限 + **按目录 mtime 缓存**（未变更则复用上次评分） | 二次扫描近乎免扫 |
| A4 重复文件哈希分级 | 三级过滤保留，但把 SHA-256 换成 BLAKE3/xxHash 做采样比对，仅最终确认用强哈希；文件级并行 `worker_threads` | I-02：160s → 100s |
| A5 轻量增量（不依赖 USN） | 按卷记录 `mtime` 水位，仅重扫变更目录——**非 NTFS 卷也适用** | 为 B1 提供兜底与过渡 |
| A6 数据库写入批量化 | sql.js 驱动下合并事务 + 降低整库落盘频率；大结果集分页写 | 消除扫描尾段卡顿 |

**验收**：枚举 ≤ 6s；全盘垃圾 ≤ 100s；缓存命中的图谱构建 ≤ 400ms。

### B · 原生能力补全（P0/P1）

| 任务 | 说明 | 依赖 |
|---|---|---|
| B1 USN Journal 增量（FR-13） | 两条路线：**(a)** 可选原生模块（Rust/Node-API，`optionalDependencies` + 运行时探测，缺失自动降级到 A5）；**(b)** 先用 `fsutil usn readjournal` 读取变更（能力受限，但零原生依赖） | 见「关键决策」 |
| B2 延迟删除落地 | 占用文件登记 `MOVEFILE_DELAY_UNTIL_REBOOT`，下次启动校验并提示结果（补全文档 5.6.1 流程） | 需注册表 `PendingFileRenameOperations` 写入 |
| B3 Restart Manager 占用检测 | 用 `RmStartSession/RmGetList` 定位占用进程，给出「关闭后即可删除」的可操作指引 | 原生调用或 PowerShell 等价实现 |
| B4 E6 证据默认可用 | CLSID 索引落库 + 后台增量更新（首扫后台建索引，之后增量），不再阻塞图谱构建 | 无 |
| B5 API Set 动态映射 | 从 `ntdll` 的 `.apiset` 节读取映射表，替换当前静态前缀表 | 无 |

### C · 稳定性与兼容性（P0）

| 任务 | 说明 |
|---|---|
| C1 双基线回归 | Win10 22H2 / Win11 23H2 建立自动化冒烟 + 人工验收清单，输出兼容矩阵 |
| C2 扫描进程隔离 | 扫描移入 `utilityProcess`（文档 4.2 原设计要求），崩溃自动重启并续扫；保留现有任务 ID/流式/可取消契约 |
| C3 路径健壮性 | 用户名含中文/空格/非 ASCII、长路径（>260 字符）、UNC、多用户账户场景 |
| C4 压力测试 | 8000+ 节点图谱、100 万文件扫描的内存与句柄曲线报告 |
| C5 本地诊断包 | 结构化日志 + 一键导出诊断包（脱敏），便于用户反馈问题 |

### D · 图谱与体验增强（P1）

|---|---|

## 四、关键决策：是否引入可选原生模块

这是 v2.0.0 唯一会动摇 v1.0.0「零原生依赖」原则的决策，B1 / B3 / B5 的路线都由它决定。

| 方案 | 优势 | 代价 |
|---|---|---|
| **纯 PowerShell / 无原生**（保持现状原则） | `npm install` 免编译；任何机器可构建；单 exe 分发 | USN 能力受限（`fsutil` 版本差异）、Restart Manager 只能近似、性能上限低 |
| **可选原生模块**（`optionalDependencies`） | USN 增量、RM 占用检测、API Set 动态映射全部可达标 | 需 CI 编译矩阵（Node ABI × 架构）；用户机器缺模块时须能优雅降级 |
| **双轨**（推荐） | 默认走无原生路径，检测到原生模块存在则启用增强 | 开发量最大，但风险最低、兼容性最好 |

**建议：双轨。** 原生模块作为可选增强，加载失败自动降级，不破坏 v1.0.0 的零依赖分发优势。

## 五、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| PowerShell 常驻会话方案复杂（A1） | 性能目标不达标 | M1 先做「并行调用」版本，常驻会话作为增量优化，留回退 |
| 原生模块编译矩阵维护成本（B1） | CI 复杂度上升 | 限定 x64 + 当前 LTS Node ABI；仅打 Windows 目标 |
| 代码签名证书申请周期长（E1） | 阻塞发布 | M0 即启动申请，M3 前拿到即可 |
| Win10 差异导致回归失败（C1） | 延期 | M0 就备好 Win10 机器，把差异前置暴露 |
| 大图性能优化收益不确定（D1） | 体验目标未达成 | 先做渲染剖析定位瓶颈，再决定是否引入离屏 Canvas / WebGL |
| sql.js 驱动无 FTS5（I-11） | 检索体验受限 | 若 Node 侧驱动可用则启用 FTS5，否则做前缀索引 + LIKE 优化 |

## 六、v2.0.0 验收清单（可量化）

- [ ] 软件清单枚举 ≤ 6 s（v1：19~28 s）
- [ ] 全盘垃圾扫描 ≤ 100 s（v1：~160 s）

- [ ] 单软件图谱构建（缓存命中）≤ 400 ms，冷启动 ≤ 3 s
- [ ] 8000 节点图谱交互 60 FPS
- [ ] 单元测试覆盖率 ≥ 70%，CI 全绿
- [ ] Windows 10 22H2 / 11 23H2 双基线回归通过
- [ ] 签名安装包在主流杀软下零误报
- [ ] 浮窗插件加载前完成清单与权限校验
- [ ] 全部删除动作可从审计日志与隔离区还原
- [ ] 文档与 Release 说明随版本同步更新
