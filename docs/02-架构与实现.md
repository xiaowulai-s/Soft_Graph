# 架构与实现

## 分层架构

严格对齐技术设计方案 4.1 的五层模型：

```
L5 表现层   Vue 3 视图（三栏布局 / 图谱画布 / 侧边栏 / 设置抽屉 / 浮窗）
              apps/desktop/src/renderer/**
L4 桥接层   Preload + contextBridge 白名单 API
              apps/desktop/src/preload/index.ts   ← 渲染层拿不到 ipcRenderer 本体
L3 服务层   扫描调度、图谱构建、垃圾规则引擎、清理执行器
              apps/desktop/src/main/services/scan.ts、float/*
L2 能力层   PE 解析 / DLL 搜索 / 图标提取 / 注册表枚举 / 插件采集
              packages/scanner/**  packages/junk/**  packages/graph-core/**
L1 数据层   SQLite（8 张表）+ 图标缓存 + PE 缓存 + 规则配置
              apps/desktop/src/main/db/**
```

跨层禁止直连：渲染层只能调用 `window.api`（白名单），无法访问 Node 与数据库。

## 关键模块要点

### PE 解析（`packages/scanner/pe.ts`）
- 解析链路：DOS Header → `e_lfanew` → PE 签名 → COFF（判 32/64 位）→ Optional Header → 数据目录
- 数据目录 1（Import）、13（Delay Import）、2（Resource：RT_MANIFEST / RT_VERSION）、14（CLR 元数据）
- **惰性 64KB 分页读取**：实测本机存在 146MB / 222MB 的单体 exe，整文件载入会瞬间吃掉数百 MB 内存。分页后解析 222MB 文件的常驻内存约 128KB
- 解析失败不抛异常，返回 `parseStatus='failed'`，上层降级为目录归属证据（对应风险 R1）

### 证据融合与置信度（`packages/scanner/deps.ts`）

| 证据 | 来源 | 权重 |
|---|---|---|
| E1 | 安装目录归属 | 0.60 |
| E2 | PE 静态导入表 | 0.90 |
| E3 | 延迟导入表 | 0.75 |
| E4 | .NET 程序集引用 | 0.90 |
| E5 | SxS 并行程序集清单 | 0.80 |
| E6 | COM 与服务注册（默认关闭） | 0.70 |
| E7 | 快捷方式关联 | 0.50 |
| E8 | 运行时映像加载（ETW） | 1.00（预留） |

```
confidence = clamp( max(E_weight) + 0.05*(hitCount-1) - 0.15*min(1, log10(refCount)/2) )
```
`refCount` 冷启动无数据库积累时对系统目录与共享运行库给保守基线（120 / 60 / 40），
确保 kernel32.dll 不会被判为某软件的专属依赖 —— 这是文档明确的设计意图。

### Windows 三大特殊机制（`packages/scanner/dllresolve.ts`）
- **API Set**：`api-ms-win-crt-*` 等虚拟 DLL 静态前缀映射回 `ucrtbase`/`kernelbase`/`sechost`；未命中的标记为虚拟而非缺失，避免数十个噪声节点
- **KnownDLLs**：经 PowerShell 读取注册表，登记项直接解析到 System32
- **WinSxS 重定向**：建立目录索引，按架构（amd64/x86）+ 版本号降序定位真实路径
- **WOW64**：按目标程序位数选择 System32 / SysWOW64，避免 x86 程序产生大量错误归属

### 图谱构建与布局（`packages/graph-core/`）
- 分组策略：系统依赖 / 共享运行库 / 插件 / 用户数据 / 缺失依赖 / 其他关联，默认折叠为聚合节点
- 布局：`d3-force` + `forceRadial`（按层目标半径）+ `forceCollide` + 自定义角度分散力；>3000 节点切换近似布局
- 收敛后坐标写入 `graph_cache`，二次打开免重算

### 垃圾规则引擎（`packages/junk/`）
- 规则 JSON 驱动：环境变量展开（含 `%SG_DRIVES%` 展开为所有固定盘符）、glob 匹配、排除、最小体积、最小存在时长
- 重复文件三级过滤：大小分组 → 头/中/尾各 64KB 采样哈希 → 全文件 SHA-256 复核；组内保留「修改最早 + 层级最浅」的一份
- 扫描结果每一项都先过安全白名单，UI 上不会出现「显示了却删不掉」的条目

### 删除执行（`packages/junk/cleaner.ts`）
```
用户勾选 → DeletePlan
[校验一] 白名单硬拦截（对规范化后的真实路径判定）
[校验二] realpath 解析 junction / 符号链接，防逃逸
[校验三] 删除前再次 stat，比对 size + mtime，防路径复用误删
→ 移动至隔离区 → 写入 manifest.json
```

### 浮窗插件（`apps/desktop/src/main/float/`）
- 契约：`{ manifest, collect(ctx), setup?, dispose? }`，见 `docs/03-插件开发.md`
- 注册表同时加载内置与外部插件，内置插件走完全相同的契约（可被禁用/排序）
- 单个插件采集超时 15s 或抛错只影响自身卡片，不影响浮窗

## 与设计方案的实现差异（Rust 原生层降级）

| 文档设计 | 本实现 | 影响 |
|---|---|---|
| Rust + napi-rs（PE/图标/USN/回收站） | 纯 TS PE 解析器 + PowerShell System.Drawing | 无 USN 增量（FR-13 一期缺）；其余能力等价 |
| API Set 从 PEB `ApiSetMap` 读取 | 静态前缀映射表 + 磁盘存在性校验 | 覆盖主要族群，未映射的标记为虚拟而非缺失 |
| better-sqlite3 + WAL | 双驱动：优先 `node:sqlite`，回退 sql.js（WASM） | FTS5 路径检索退化为 LIKE |
| Restart Manager 占用检测 | 移动失败按 `errno` 判定 + PowerShell 反查占用进程 | 少了「主动关闭进程」一步 |
| utilityProcess 扫描隔离 | 主进程执行，保留任务 ID/流式分批/可取消契约 | 扫描时 IPC 响应略延迟，渲染进程独立故 UI 不冻结 |
| `reg.exe` / `MsiEnumProducts` | PowerShell .NET Registry API + JSON 文件管道 | 规避控制台代码页乱码（中文软件名完好）与安全策略拦截 |

## 数据流

```
UI 点击「扫描」
  → IPC scan:software:start
  → 主进程创建任务（可取消），PowerShell 枚举五来源
  → scan:software:progress / batch 流式回传，UI 边扫边画
  → 结果写入 software 表；图标批量提取落盘
  → 选中软件 → graph:build → PE 解析 → 证据融合 → 建图 → 布局 Worker → 渲染
  → 垃圾扫描 → 规则引擎 → junk_item 表 → 侧栏环形图
  → 勾选删除 → 三重校验 → 隔离区 + manifest → 统计刷新
```
